4. **The cross-game route is documented by AnvilToolkit itself** (wiki "Creating Custom Animations"):
   - An `.Animation` is skeleton-agnostic: its tracks are keyed by **bone-name hash**, at 60 fps.
   - **To move a clip between games, export it to XML on Unity and import the XML on Syndicate.** The `.Animation` save
     is locked to the game it was loaded from.
   - Before a GLB export, **load every skeleton the clip uses**. Missing bones are dropped silently.
   - To use a clip, **replace** an existing ID, or **add it under a new ID and repoint the AnimSet's
     `TargetAnimation`**. That's the sanctioned way to add clips; it's not the same as adding records to pack 6969, which
     crashed (m2).
   - Supporting evidence: Syndicate's Élise outfit textures are named `CN_U_FR_Elise2_*`, a Unity asset Ubisoft ported
     into Syndicate. Unity skeletons are `ACU_BaseSkeleton_Male` (DataPC) and `ACU_BaseSkeleton_Female`. Syndicate's are
     `ACVI_CHR_SHR_Male` and `ACVI_CHR_SHR_Female`.
5. **Reference map: probably skip writing `dbg/refmap.py`.** AnvilToolkit-Resources ships `Reference Maps/Syndicate.refmap`
   and `Unity.refmap`, its own "what points at what" maps. They're Oodle-packed in a way the open-source decoder can't
   read, but AnvilToolkit loads them itself. Check ATK's UI (Game Explorer context menu or Extra Utilities) for a
   references/usages lookup before building our own.
6. **ACViewer ≥ 0.2.21 exports animations to FBX** (all skeleton poses as takes; 0.2.25-3 adds all LODs to FBX/USD).
   The session on 2026-10-09 concluded that ACViewer can't export animations, so it may have been on an older build.
   If a newer one exports Syndicate/Unity clips, previews no longer need UTM. It's unverified for these two games.
